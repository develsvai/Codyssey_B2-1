# 구조 및 저장 계약

미션 B2-1의 필수 기능을 Python 3.10 이상 표준 라이브러리만으로 구현한다.

## 의존성

`__main__`은 객체 연결을 담당한다. `cli → services → infrastructure → domain → common` 방향만 허용한다.
상위 계층이 더 아래 계층을 참조하는 것은 허용하되 CLI 명령은 저장소를 직접 호출하지 않는다.
기능 서비스 간 호출은 사용하지 않는다. 여러 저장소가 필요한 요약·CSV·카테고리 삭제 절차는 해당 서비스가 조정한다.
모델과 검증은 파일이나 화면을 모르며 common은 프로젝트의 다른 계층을 import하지 않는다.
`input`/`print`/종료 코드는 CLI에만 둔다. 오류 타입은 common, 오류 안내 데코레이터는 CLI,
시간 측정 데코레이터는 common에 둔다. 도메인 규칙을 범용 유틸리티로 숨기지 않는다.

## 영구 저장과 순서

- 기본 `./data`, `--data-dir`로 변경. `transactions.jsonl`, `categories.jsonl`, `budgets.jsonl`을 생성한다.
- 기본 카테고리는 food, transport, rent, salary, etc. 처음 생성할 때만 기본값을 넣고,
  기존 빈 카테고리 파일은 사용자가 비운 것으로 취급한다. category add로 등록하도록 안내한다.
- 거래 필드는 id/type/date/amount/category/memo/tags. 금액은 양수 정수, ID는 UUID 기반이다.
- 거래 파일은 `(date, id)` 내림차순으로 유지한다. 같은 날짜에서는 ID 내림차순으로 정렬한다.
  새 거래·수정은 정렬된 파일과 병합해 쓴다. 목록·검색은 한 줄씩 yield하며 전체를 메모리에 적재하지 않는다.
- 파일 수정은 같은 디렉터리의 임시 파일에 쓰고 flush/fsync 후 os.replace한다. 검증/쓰기 실패 시
  임시 파일을 삭제하고 원본을 보존한다. 쓰기 잠금은 데이터 디렉터리 전체를 보호해 참조 검증과 저장을 묶는다.
- 손상된 JSONL은 위치와 복구 힌트를 제공하고 덮어쓰지 않는다. 외부 수동 편집은 지원하지 않는다.

## 기능 정책

- add는 대화형, update는 옵션 방식으로 고정하며 ID 변경은 금지한다.
- 등록되지 않은 카테고리와 없는 ID는 오류. 사용 중 카테고리 삭제는 금지한다.
- 검색 조건은 AND로 결합한다. 날짜 양끝을 포함하고 메모 키워드는 대소문자를 무시하며 태그는 정확히 비교한다.
- summary는 총수입/지출/잔액, 지출 TOP N, 월 예산 사용률과 엄격한 초과 여부(지출 > 예산)를 계산한다.
- export는 월 또는 시작일·종료일 쌍 중 하나를 필수로 받고 동시에 지정하면 오류다.
- CSV는 UTF-8, 헤더 포함. 필수 date/type/category/amount, 선택 memo/tags.
  태그는 쉼표 구분이며 CSV 인용은 csv 모듈이 담당한다. ID는 가져올 때 새로 생성한다.
- import는 전체 검증 성공 시에만 반영한다. 잘못된 행은 행 번호와 원인을 안내한다.
  재가져오기는 별도 거래 추가로 취급한다. 정렬이 필요한 대량 입력은 디스크 임시 파일을 이용한다.
- 정상 종료 0, 입력/업무/저장 오류 비0. 스택트레이스를 화면에 노출하지 않는다.

## 검증

unittest로 모델, 파일 실패 보존, 서비스 규칙, CLI 실제 실행, CSV 왕복을 검증한다.
AST 기반 검사로 하향 import, 순환 의존성, 하위 계층의 화면 입출력 금지를 검증한다.
백업 명령과 반복 거래는 선택 과제로 구현 범위에서 제외한다.
