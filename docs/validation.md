## 데이터 안정성과 스트리밍

- 파일 교체 실패와 생성기 중간 오류를 주입해 원본 보존 및 임시 파일 정리를 확인했다.
- 손상 JSONL을 읽거나 변경할 때 오류를 안내하고 원본을 보존한다.
- 날짜가 뒤섞인 CSV 2,300건을 작은 청크/병합 폭으로 설정해 다단계 외부 병합을 검증했다.
- 거래 12,000건 검색을 소비하는 동안 tracemalloc 최대 메모리가 1,000,000 bytes 미만이었다.
- limit 1 조회는 다음 레코드를 읽지 않는다.
- 한글, 쉼표, 따옴표, 줄바꿈, 긴 메모 및 태그의 CSV 왕복을 검증했다.
- 뒤쪽 오류 행의 전체 반영 취소, 저장 파일·심볼릭 링크 대상 덮어쓰기 차단, ID 충돌 시 원본 보존을 검증했다.

## 통합 과정에서 수정한 결함

1. CSV 기본 필드 크기 제한으로 긴 메모의 재가져오기가 실패했다. 파싱 중 필드 제한을 확장하고 종료 시 복원한다.
2. 내부 저장 파일 자체가 심볼릭 링크인 경우 실제 대상 경로의 내보내기를 막지 못했다. 보호 경로를 resolve해 비교한다.
3. 강제로 재현한 가져오기 배치 ID 충돌이 날짜가 다른 거래의 중복 ID를 만들 수 있었다. 기존 배치 접두어를 검사해 거부한다.

세 결함 모두 실패 재현 테스트를 먼저 확인하고 수정 후 전체 테스트를 통과했다.

## 요구사항 재점검 후 보완

- export가 월 또는 기간 중 정확히 하나만 받던 제한을 제거했다. 월과 기간을 함께 지정하면 서비스에서 두 조건을 AND로 적용한다.
- 기간의 양끝 포함, 월보다 좁거나 넓은 기간, 월 경계, 윤년의 2월 29일, 겹치지 않는 기간을 회귀 테스트로 검증했다.
- 잘못된 월·날짜, 역전된 기간, 시작일/종료일 중 하나만 지정한 경우 오류를 내고 기존 출력 파일을 보존한다.
- 기존 구현에서 교집합 관련 테스트 실패를 확인한 후 수정했다. 서비스 테스트 4개와 실제 CLI 테스트 1개를 추가해 전체 70개가 통과했다.
- 하향 의존성, 스트리밍 처리, CSV 직렬화와 원자적 파일 교체의 공통 계층 배치는 유지했다.

- 표준 라이브러리만 사용한다. 백업 명령·반복 거래·가변 폭 표 정렬은 선택 과제로 제외했다.
