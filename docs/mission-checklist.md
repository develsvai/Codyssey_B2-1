# 미션 원문 대비 재점검

점검일: 2026-11-10 (Asia/Seoul)

최초 점검 대상: 저장소의 미션 B2-1 PDF 11쪽 전체와 `79c3b54` 시점 애플리케이션.
최초에는 기능 코드를 변경하지 않고 대조했으며, 이후 Loom 후속 작업에서 export 교집합 처리를 보완했다.
아래 판정과 표는 보완 결과를 반영한다. 최초 점검 당시 실행 근거는 마지막 절에 보존했다.

## 판정

최초 점검에서 38개 충족, export 조건 조합 1개 검토 필요로 분류했다.
후속 작업에서 월과 기간을 동시에 받아 교집합을 내보내도록 보완하여 아래 39개 항목 모두 충족으로 판단한다.
선택 과제인 백업, 반복 내역, 표 정렬의 미구현은 필수 누락에 포함하지 않는다.

## 해석 차이와 보완: export 조건 조합

PDF 6쪽은 월 조건 또는 시작일·종료일 조건 중 **하나 이상**을 요구한다.
최초 점검 당시 `services/transfer.py`는 둘 중 정확히 하나만 받으며 두 조건을 같이 주면 종료 코드 2로 거부했다.
당시 README와 테스트도 이 배타적인 선택 정책에 맞춰 작성되어 있었다.

최초 문제를 재현했던 명령 (현재는 교집합 내보내기 성공):

```bash
python3 -m budget_app export --out out.csv --month 2024-01 --from 2024-01-10 --to 2024-01-20
```

보완 전 결과:

```text
[오류] 월과 기간 조건을 동시에 지정했습니다.
[힌트] --month 또는 --from/--to 쌍 중 하나를 사용하세요.
```

원문은 두 조건을 동시에 받은 경우의 교집합/우선순위를 정의하지 않아 당시 확정적인 누락으로 단정하지 않았다.
후속 작업 `task-20261110-075131-csv-export-6a694fd1`에서 서비스가 두 조건을 AND로 결합하도록 구현했다.
위 명령은 현재 2024-01-10~2024-01-20의 거래를 출력한다. 겹치는 기간이 없으면 헤더만 있는 CSV를 정상 생성한다.
월 단독과 기간 단독은 계속 지원하며, 기간을 주면 시작일·종료일은 모두 필요하다.
CLI 도움말, README, 구조 문서와 회귀 테스트도 같은 정책으로 갱신했다.

## 최초 재점검 실행 근거

1. `python3 -W error::ResourceWarning -m unittest discover -v`: Python 3.14.4에서 65개 전부 통과.
2. 기존 테스트와 별도로 임시 폴더에서 실제 CLI 54회 실행, 10개 시나리오 전부 통과:
   help/옵션, 초기화/빈 카테고리, add 재입력, 기본 limit, 개별 검색,
   update 전체 필드/실패 보존, 예산·집계, 카테고리 삭제, CSV 월·기간 교환, 최소 CSV 스키마.
3. 월·기간 동시 export를 추가 1회 실행해 위 해석 차이의 실제 오류 응답 확인.
4. 전체 앱의 dataclass 필드, 클래스 20개, Python 파일 38개 확인.
5. 운영 코드와 기존 테스트는 변경하지 않았다. 점검 보고서와 Loom 실행 기록만 추가했다.

## 후속 보완 검증

- 월·기간 교집합 처리를 구현하고 서비스 테스트 4개, 실제 CLI 테스트 1개를 추가했다.
